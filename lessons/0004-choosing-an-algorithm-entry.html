选择算法接入边界

同一个算法可以“跑起来”于多个位置，但只有部分路径保留实验身份、诊断和可复现证据。

完成标准：面对传统算法、外部 MPC、神经网络推理或 RL 训练，能选出当前项目中正确入口。

统一入口：IntegrationRegistry

ExperimentRunner.prepare() 不直接认识算法类。它把稳定 algorithm_id 和配置交给 IntegrationRegistry.build_algorithm()，再把构造出的 ICOLAV 安装到 Ship0。

四条接入路径

1. 内置算法

nominal、vo、sbmpc 在 registry 内显式构造。适合成为仓库长期能力的核心算法，但需要改 registry、能力目录、配置与测试。

2. 动态 CustomMPC 插件

配置提供 factory="module:callable"。factory 接收 FactoryContext，当前实现强制返回 core/colav/CustomMPCAdapter。适合不修改 registry 便接入新 MPC 或可表达为 solve 函数的策略推理。

3. 固定外部集成

integrations/psbmpc.py、rrt.py、sbmpc_reference.py 等负责把外部仓库 API 包装成 ICOLAV。适合依赖安装、数据转换或生命周期复杂的算法。

4. RL 训练环境

COLAVEnvironment 使用 remote_actor=True，让 agent 外部提供 action/reference。它解决训练交互，不等同于把训练完成的策略部署为可审计 COLAV 插件。

当前限制：动态 factory 名义上返回 ICOLAV，运行时却检查必须是 CustomMPCAdapter。任意新 ICOLAV 不能仅靠 factory 动态加载；需新增 registry 分支或扩展工厂契约。

深度学习算法如何选

  • 训练：COLAVEnvironment。设计 observation、action、reward、termination。
  • 离线策略评估：把模型推理包装成确定性 solve，输出 MPCSolution；通过 plugin 记录模型与依赖身份。
  • 在线部署研究：除推理输出，还需 deadline、模型版本、归一化参数、隐藏状态 reset、失败状态和禁止 fallback。

不要选错同名类

仓库存在两个 CustomMPCAdapter：

  1. core/colav/custom_mpc_adapter.py：实现 ICOLAV，带 typed input、solution、deadline、diagnostics、build identity。当前实验插件路径使用它。
  2. guidance/custom_mpc_adapter.py：实现 IGuidance，委托给可切换 solver。处于 guidance 分支，不满足当前 plugin factory 的类型检查。

源码锚点

  • IntegrationRegistry：算法选择和 plugin factory。
  • ICOLAV：通用规划器接口。
  • Core CustomMPCAdapter：当前动态插件契约。
  • COLAVEnvironment：RL 训练入口。
