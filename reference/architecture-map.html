架构速查

先判断正在处理哪一层，再决定读哪个模块、改哪个契约、跑哪组测试。

三层系统

交互层web_gui/ + gui_server/：配置、控制、遥测整形、WebSocket、Canvas。
实验层experiment/ + evaluation/：RunSpec、能力门、会话状态、证据、指标。
科学内核scenario_generator.py + simulator.py + core/：世界、感知、规划、控制、动力学。

一次时间步

WebSessionManager.tick -> SimulationSession.advance -> Simulator.step -> 每艘船执行 track_obstacles -> plan -> 记录数据 -> forward -> 更新时间。

算法接入选择

已有传统 COLAV
ICOLAV
直接满足通用规划接口。
新 MPC 插件
CustomMPCAdapter
使用强类型输入、解与诊断。
在线策略推理
ICOLAV 或插件
策略输出必须转成 9xN references。
RL 训练
COLAVEnvironment
remote_actor=True 绕过 Ship0 内部规划。

关键契约

  • RunSpec：请求运行什么，不等于实际执行了什么。
  • PlannerInput：ENU、SI、rad；自船状态、航路、目标航迹、ENC、扰动。
  • MPCSolution：9x1 控制参考、9xN 预测轨迹、状态、可行性和诊断。
  • PlannerTrace：证明何时求解、执行哪个算法、选中什么命令。
  • SessionSnapshot：一次版本化仿真帧，不等于评价结论。

修改前四问

  1. 输入来自 truth、measurement 还是 tracker？
  2. 输出是轨迹、course/speed reference，还是低层力/舵桨指令？
  3. 失败、超时、不可行如何显式呈现，是否禁止 fallback？
  4. 验证的是 Ship0 安全、全船安全、COLREG 行为，还是论文复现？
