## D. Verdict

1. **No existing candidate covers deep Config visual fidelity.** C1's objective was structural/functional and delivered that skeleton; its acceptance never included component/token-level fidelity (rows 10-12, 15-16, 18-21 = C1 under-delivery). C3/C4 explicitly disclaim Config visual work. C5 owns only cross-workface shell chrome (rows 1-9, 22). Rows 13-14 are owned by nobody (`new-visual-pass` residue).
2. **Recommendation: dedicated Config visual pass after C3, before C4/C5.** C3/C4 don't touch config-shell.js render functions or Config markup, so no mutual invalidation; C5 should consume the token layer this pass introduces (prototype P:64-99 as reference token sheet, C5 generalizes shell-wide). Do not fold into C5 — its YAGNI rule would pressure-cut Config-interior fidelity.
3. **Size: L (large-but-bounded)** — ~13 gap rows touching all config-shell.js render functions + most of index.html Config markup + new token layer in style.css; zero backend or validation-assembly.js changes; 1-2 focused sessions of pure presentation work.
