# Threat Lifecycle Owns Historical Algorithm Handoff

> **Status**: accepted (2026-08-25)

The ten-minute Historical AIS Counterfactual session keeps the Reference Vessel on its factual AIS motion while targets progress through canonical Threat Management. The selected algorithm may compute from session start but receives control atomically only when the canonical Encounter Lifecycle first reaches `ACTIVE`; fixed-time T0 would switch before demonstrated need, `NEXT` would confuse prediction with a current duty, and waiting for current-domain violation would act too late. This handoff is the session's only branch: algorithm control is never returned to historical motion, including after `CLEAR` or `RELEASED`, so avoidance clearance and mission-route recovery remain observable algorithm behavior. The factual continuation remains visible as Shadow Ownship but is comparison-only and cannot enter tracking, Threat Management, Planner input, control, collision detection, or realized counterfactual evaluation.

## Consequences

- Before handoff, one Ownship symbol follows Historical Reference motion. At handoff, the map and timeline show one `ALGORITHM_HANDOFF` branch marker.
- After handoff, Counterfactual Ownship remains the normal solid Ownship; Shadow Ownship uses a distinct semi-transparent purple vessel, dashed trail, and `AIS SHADOW` label without radar, domain, threat, or target semantics.
- The map shows same-time Shadow Deviation by default. This comparison value cannot become DCPA, hull clearance, evaluator safety evidence, or Planner input.
- The replacement scene selects causal source evidence from `2026-07-01T11:59:07Z` through `12:10:07Z`, but its playable interval is `12:00:07Z` through `12:10:07Z`: simulation elapsed time `0..600s` maps exactly to AIS UTC. The 60-second lookback supports playback reconstruction and pre-handoff Mission Route inference only; no actor is back-extrapolated into a missing interval.
- Historical AIS executes as a Live Counterfactual Session in Deployment for every product algorithm. Precomputed or cached algorithm-result playback is rejected because it would give this scene a different runtime meaning from other Active Sessions; requested playback rate remains a scheduler request whose measured effective rate may be lower when solver cost dominates.
- Deployment retains the `1x`, `2x`, and `5x` request controls for every algorithm. The selected button represents only the requested multiplier; the adjacent actual-rate readout shows the measured effective multiplier and makes no promise that solver-bound execution will attain the request.
- The ten-minute scene replaces, rather than supplements, `hais_romsdal_20260701_120000_120100`. Its canonical ID is `hais_romsdal_20260701_120007_121007`; the old ID has no catalog or API alias, and its one-minute Dataset, actor, Case, Human Reference, determinism, Compare, and qualification evidence cannot be inherited by the replacement.
- Deployment adds a backend-owned Shadow Comparison. During execution it publishes handoff time, Shadow Deviation, course/speed deltas, and maximum divergence; after execution it separately summarizes realized minimum hull clearances, closest-approach times, voyage-distance delta, clearance, and mission-route recovery for Counterfactual and factual trajectories. The browser only projects this document, and it cannot issue an Independent Evaluator verdict or assume algorithmic superiority.
- Catalog publication requires Historical Display Qualification produced by the same canonical lifecycle/threat chain over the bounded factual window. A window that does not naturally reach `RiskPhase.ACTIVE` is not displayed or selectable; runtime cannot substitute fixed T0, lowered thresholds, or forced activation, and an unexpected non-trigger is reported as `HANDOFF_NOT_TRIGGERED` with Counterfactual avoidance `NOT_EXECUTED`.
- Historical Display Qualification requires at least one target, not every target, to reach `ACTIVE`. Every other published Historical Actor remains a visible Traffic Context Target even when it stays `MONITOR` or `CLEAR`; risk state cannot filter real same-window traffic from the map.
- The source selection retains all 35 AIS contacts for immutable lineage. Runtime admits only Ownship plus the three user-accepted, continuously moving local contacts (`257252000`, `258764000`, `259257000`); stationary/harbour context is neither rendered nor silently passed to the algorithm. The retained unknown hull uses the visible, versioned Assumed Historical Hull and participates in tracker, Threat Management, Planner, Ship Domain, and collision evaluation.
- `ASSUMED_HULL.v1` is `85m` length, `16m` width, and `3m` draft, rounded from the largest currently proven target hull in this bounded scene. Its provenance remains `ASSUMED`; it cannot be presented as the vessel's real type or dimensions.
- Sparse AIS remains source-preserving: observed reports are retained, gaps up to `300s` use endpoint-exact linear UTM position/velocity interpolation, and no state is extrapolated before the first or after the last report. Every interpolated segment must remain inside qualified navigable ENC water; an invalid or larger gap is `INACTIVE / DATA GAP`, and a returning MMSI starts a new tracker generation. Deployment labels `OBSERVED`, `INTERPOLATED`, and `INACTIVE / DATA GAP` without spline smoothing or invented land-avoiding routes.
- Deployment defaults to an Ownship-Follow View with `6NM` total horizontal span: Historical Reference Ownship before handoff and Counterfactual Ownship after handoff. A purple edge indicator gives off-screen Shadow bearing/range; `Fit Traffic` frames active actors, Shadow, and the real mission route, manual pan/zoom suspends follow, and `Recenter` restores it. The synthetic `10km` guidance extension is not a visible waypoint or fit input.
- Product tuples require Historical Algorithm Qualification over all three admitted targets and the full `600s` Live Counterfactual Session. VO and Fan-MPC remain Experimental pending fresh no-pruning/no-fallback qualification over this exact actor set. Mid-MPC remains unselectable because no Historical Algorithm Qualification exists for the revised scene; the smaller actor set does not manufacture evidence.
- The scenario seals a three-point Historical Reference Route before execution from factual Ownship AIS: WPT1 is the playback-start observation (`12:00:07Z`, `62.475876N 6.146200E`), WPT3 is the final observation (`12:10:05Z`, `62.463684N 6.067577E`), and WPT2 is the observed point with maximum perpendicular deviation from the WPT1-WPT3 chord (`12:06:16Z`, `62.478577N 6.093765E`). Planner receives only this content-addressed route geometry; runtime Shadow updates, future timestamps/commands, and all target futures remain excluded. Recovery uses the nearest route leg and completes only after every relevant target is `RELEASED` and Counterfactual Ownship sustains at most `100m` cross-track error and `5deg` course error for the final continuous `30s`.
