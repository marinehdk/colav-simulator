# VO 决策圈与显示缓冲同步

2026-09-10，基于 `31558544`。

## 根因

前端以约 3 秒缓冲播放遥测帧，并用该帧的真实 solve ID 请求密集 VO 决策空间。旧接口只读取算法当前最新决策矩阵：执行端前进后，请求已显示但较旧的 solve 会返回 HTTP 409，前端因而保留先前的决策圈内容。鼠标操作可以触发额外重绘，但不能解决缺失的历史决策快照。

最小实机复现：solve 369 首次请求为200，前进8个单步后同一请求返回409，服务端最新为373。独立 API 回归进一步验证：即使浏览器从未提前请求过旧矩阵，延迟第一次请求也必须成功。

## 修复

- 在发布 VO 遥测时留存该次真实求解的决策空间；按 solve ID 获取，不返回另一轮矩阵替代。
- 保留最近64次已发布求解；HOLD不重复复制，切换/重置会话清空。超过保留窗口仍明确返回409。
- 密集矩阵继续通过按需接口返回，不塞入每帧 WebSocket 遥测。3秒缓冲与倍速机制不变。
- HDG、COG、ROT取消固定宽度补零；本船和航线的航向文本同步处理。时间格式、深度、航速及算法数值不变。

- `canvas.log`：31 passed，新增1×/5×无指针事件、同源序列下的缓冲位置更新测试。决策圈与本船使用同一绘制位置。
- `frontend.log`：前端257 passed。浏览器确认HDG/COG普通整数显示，ROT无额外前导零。

部署时发现8010由昨日独立进程占用，LaunchAgent重启曾因端口冲突未生效。确认路径、启动命令和暂停状态后终止该旧进程，由托管服务接管，再重建原VO配置进行上述实机检查。最后保持会话暂停。

防回归原则：延迟显示引用的按需诊断数据必须有对应保留窗口，不能假定浏览器正在显示执行端最新solve。此修改不改变VO求解、安全阈值或船体执行。
